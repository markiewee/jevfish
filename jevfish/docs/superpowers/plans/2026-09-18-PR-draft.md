Two PRs, because the tracks are independent and reviewable separately.

## PR 1: `fix/frame-dictates-the-answer`

**Title:** Stop the frame writing the answer, and start scoring predictions

### What this changes

JevFish's demand curves were being written by the frame generator, not measured. This adds
a validator that refuses the wording responsible, a scoring module, an anchor store, a
calibration layer, and honest intervals.

### Why

On the one real backtest we have (Pureloft Suasana KL, 801 people, five nightly rates,
actual outcome 89.2 percent occupancy over 610 resolved nights), the LLM wrote comparative
notes into each option: "a third below the current rate", "two thirds above the current
rate". Re-running the identical ladder with those phrases replaced by neutral text of the
same length:

| Per-option wording | Fitted elasticity | Recommends |
|---|---|---|
| as shipped | **-1.432** | cut to MYR 250 |
| neutral, same length | **-0.090** | raise to MYR 500 |
| removed entirely | -0.113 | raise to MYR 500 |

Nothing about the property, the dates or the crowd changed. One adjective per option
decided a revenue recommendation and pointed it the opposite way. The `-0.893` previously
recorded as "inside the published range" was an artifact of the same mechanism.

`normalize_frame` passed variant text straight through with no content validation, and
`FRAME_SYSTEM` said "the first variant is the status quo", which invited it. The rule
against option-specific detail already existed one field away, applied to the outcome
question and stance levels but not to the variant values themselves.

Two further measured problems, same run:

- The reported 90 percent half-width was 2.82pp against an actual error of 32.4pp, an
  **11.5x understatement**. Because it is Poisson-binomial noise over a synthetic crowd,
  it shrinks as 1/sqrt(n) while the real error does not move, so adding people made the
  tool more confidently wrong.
- Across all 801 people the minimum probability was 0.35 and the maximum 0.72, and Jev
  returned only 30 distinct values, four of which covered 341 people. A mean of numbers
  trapped in that band cannot reach 0.892.

### What is in it

- `frame_audit.py`: detects comparative per-option language, produces a neutralised frame,
  reports whether a result survives neutral wording, and blocks curves that are flat, run
  the wrong way, or are steeper than any published estimate.
- `frame.py`: `normalize_frame` now raises `FrameError` on comparative variant wording, and
  `FRAME_SYSTEM` forbids it explicitly.
- `scoring.py`: Brier, log score, CRPS, a level-versus-shape decomposition, and a skill
  score against a named baseline. ECE is deliberately absent because it is not a proper
  scoring rule.
- `anchors.py`: resolved outcomes on disk, each carrying its `estimand`, `model_version`
  and `frame_hash`, because a calibration fitted on one model version does not transfer.
- `calibrate.py`: `sigmoid(a + b*logit(q))` applied per persona **before** aggregation,
  plus split-conformal half-widths. Strictly monotone, so it can never reorder the options.
- `metrics.py`: `summarize_poll` gains optional `calibration`, `honest_half_width` and
  `estimand` arguments, reports the estimand's plain-English label, and states which kind
  of interval is in force. All arguments default to the existing behaviour.
- `policy.py`: `ChoiceQ` option order is randomised per person, deterministic in the seed
  so the request cache still hits. The `NoulQ` outcome path is untouched, since it has no
  option list to bias.

### What is deliberately not in it

- **Persona enrichment.** Measured: adding concrete budgets, party sizes and shortlisted
  alternatives raised the crowd's standard deviation 2.4x, from 0.080 to 0.192, and moved
  the mean 0.08 *further* from the truth. The literature agrees it buys spread and not
  accuracy: 500-question digital twins score 0.748 against 0.734 for an empty persona.
- **The Gui and Toubia exogeneity sentence.** Their published effect is large (elasticity
  0.14 to 1.38 across 40 categories). On Jev, with the frame artifact neutralised first so
  it could not mask anything, it moved elasticity by **0.001** and narrowed the crowd. Their
  mechanism needs a generative model inferring confounders while it writes; Jev writes
  nothing. Recorded as a negative result rather than shipped on the paper's authority.
- **Extremising.** Ruled out, not deferred. It is justified when forecasters hold partly
  independent information, and a crowd drawn from one frame and one model does not. Our own
  test confirms it: exponents of 2.0 and 3.0 both wrecked the curve.
- **Changing the aggregation rule.** The arithmetic mean is a linear opinion pool, the pool
  matched to Brier. It was never the problem.

### Honest limits

The one-anchor calibration removes the level error *by construction*, which is not a
validated gain. Validating it needs enough anchors to hold one out, and Pureloft's own data
cannot supply them: its measured elasticity comes out positive (+0.17 to -0.02) because
rates were raised on nights already expected to fill. With no anchors the calibration is
the identity map and the output is labelled "uncalibrated".

`mean_outcome` is a share of a described option set, not occupancy. A listing with a
22 percent choice share can sit in a flat running at 89 percent occupancy. This PR makes
JevFish say that rather than fixing it, because fixing it needs arrival volume and listing
visibility, which JevFish does not have.

### Testing

- 84 existing tests still pass; every new argument defaults to current behaviour.
- New: `test_frame_audit.py` (13), `test_scoring.py` (5), `test_anchors.py` (4),
  `test_calibrate.py` (7), `test_metrics_calibration.py` (6), `test_policy_order.py` (4).
- `test_pureloft_regression.py` pins every number quoted above to the stored run, so none
  of it can silently regress.
- Offline end-to-end check: `JEVFISH_FAKE_JUDGE=1 JEVFISH_FAKE_LLM=1 jevfish demo
  --platform lite` completes all five stages.

## PR 2: `feat/installable-and-findable`

**Title:** Make JevFish installable in one line and findable at all

### What this changes

Packaging and presentation. No change to how a run executes.

### Why

| Check | Before |
|---|---|
| `search/repositories?q=mirofish-jev` | **0** results. With `fork:true`, 1. GitHub excludes forks from search and topic pages |
| Repo identity | named `mirofish-jev`, MiroFish's description, homepage `mirofish.ai`, 0 topics |
| `uv build --wheel` | 34 files, **no `web_dist`**. An installed copy serves `/` as a 404 |
| venv | **1.1 GB**, 161 packages. torch is 553 MB and is never called |
| `requires-python` | `>=3.12,<3.13` |
| `mcp==1.24.0` | declared, zero imports anywhere |
| `pymupdf` | AGPL-3.0, a copyleft obligation independent of MiroFish |
| README | first code block at line 112; 37 MiroFish mentions to 4 JevFish |

`MiroFish-Offline`, detached with 10 topics, has 2,522 stars. `mirofish-offline`, a fork
with 0 topics and a byte-identical description, has 0.

The code was already ready for the size fix: `make_platform` and the PDF reader both
already import lazily. Only the dependency declaration forced the 1.1 GB download. Proved
by building a 26 MB venv with four packages and running the whole pipeline in it.

### What is in it

- `assets.py`: the one module that knows where files live. Read-only assets resolve through
  `importlib.resources`; anything writable goes to a per-user directory. Replaces
  `PACKAGE_ROOT = parents[2]`, which pointed into `site-packages` once installed.
- `web/dist` moves to `src/jevfish/web_dist`, `examples` to `src/jevfish/examples`, both
  declared as package data. CI fails the release if the wheel lacks either.
- `camel-ai`, `camel-oasis` and PDF support become optional extras. `pymupdf` becomes
  `pypdf` (BSD-3-Clause), removing 54 MB and an AGPL obligation. `mcp` is dropped.
  `make_platform` raises a message naming the extra to install and pointing at `lite`.
- PyPI metadata carrying the words the audience actually searches (silicon sampling,
  synthetic respondents, synthetic survey, AI focus group), plus a release workflow.
- New root README leading with the keyless demo, which already works and was invisible,
  then the one-line install, then a hero GIF at 300 to 900 KB and a calibration plot.
  MiroFish's README moves to `docs/UPSTREAM-README.md`.
- AGPL compliance: a dated modification notice (section 5(a)), a licence section in prose
  (5(b)), `NOTICE` (section 4), `THIRD_PARTY.md`, and a source pointer in release bodies
  (6(d)). Deletes `.github/workflows/update-star-history.yml`, 18 KB of scheduled job
  charting upstream's star count, and the three badges reporting upstream's numbers.
- `CONTRIBUTING.md`, an issue form that asks how the app was launched, a social preview
  image, a static replay demo on GitHub Pages, and a DMG with a version-free asset name.
- Two defects found by screenshot: the OASIS layer printing a raw profile dict per agent to
  stdout, and the report page's stance-axis labels overlapping illegibly.

### Needs a decision before merge

**Leaving the fork network** is self-service, free, preserves git history and AGPL
provenance, and redirects the old URL, but cannot be undone through the UI. Verified safe:
0 stars, 0 forks, 0 open issues. Everything else in this PR is independent of it.

### Deferred, with reasons

Apple notarization (USD 99 a year to seal a 148 KB launcher around 1 GB fetched at
runtime). PyInstaller or Nuitka freezing (30 to 60 hours, and cheaper after the size fix).
Tauri (60 to 120 hours). An interactive hosted demo (the static replay gets the credibility
with no hosting bill and no AGPL section 13 exposure). Docker is documented as a Linux path
but never the headline, because Docker Desktop costs the visitor about 6 GB and a licensing
question. Renaming away from "Jev" is not warranted, though a manual USPTO check of `JEV`
in classes 9 and 42 is outstanding before any commercial use.

### Testing

- `test_assets.py`: the UI and example resolve, and the data directory is writable and
  outside the package.
- `test_optional_extras.py`: `lite` needs nothing optional, and a `reddit` run without the
  extra raises a message naming the install command.
- Clean-install check: build the wheel, install into a fresh venv, `curl /` returns **200**.
- Python 3.13 is verified with a real run before the claim goes in the README, and the plan
  says to narrow `requires-python` rather than widen it on assumption.
