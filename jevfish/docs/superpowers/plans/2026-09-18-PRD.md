# JevFish PRD: a prediction tool people will download and can trust

**Status:** approved by Mark, 18 September 2026. Both tracks, accuracy first. Fork detach
and rename to `jevfish` approved.
**Date:** 18 September 2026

> **Correction applied after approval.** An earlier version of this PRD, and the version
> pasted to Mark in chat, quoted a "Cornell benchmark of -0.36" and a "published
> property-level range of -0.13 to -0.95". **Both are unsourced.** -0.36 is in neither
> Corgel, Lane and Woodworth (2012) nor Enz, Canina and van der Rest (2015), and the latter
> does not measure elasticity at all. The supported figures are market-level: Singh and
> Corsun (2023), -0.165 short run and -0.79 long run. Corgel et al. further state that
> individual-property elasticity should be *higher* than market level, so a single property
> can legitimately exceed -0.9.
>
> **This does not change the plan.** The load-bearing finding is that identical inputs
> produce -1.432 or -0.090 depending on one adjective per option, which needs no benchmark
> to be damning. What it changes: the tool must not judge plausibility against a hidden
> elasticity constant, so `curve_check` now requires the caller to state its ceiling and
> repeats it in the message. The "raise the Pureloft rate" conclusion also survives, on
> better evidence: sustained 89 percent occupancy against a 26 to 37 percent break-even,
> and Enz et al.'s measured finding that hotels priced above their comp set earned higher
> relative RevPAR despite lower occupancy.

## 1. The problem, in two sentences

Nobody can find JevFish, and nobody should yet trust its numbers. The repo is a GitHub
fork, which makes it invisible to GitHub search; and the one number the tool exists to
produce was, on our only real backtest, decided by an adjective the frame generator wrote
rather than by anything about the world.

no camel, no torch and no pymupdf present.

### The prediction cannot currently be trusted

On the Pureloft backtest, 801 people at five rates, truth 89.2 percent occupancy:

| Finding | Number |
|---|---|
| Level error | **-32.4pp** (predicted 0.568) |
| Reported 90 percent half-width | 2.82pp, so the error was **11.5x** the stated uncertainty |
| Interval behaviour | shrinks as 1/sqrt(n) while the error does not move, so more people means more confidence and the same error |
| Crowd spread | min 0.35, max 0.72 across all 801. Nobody would definitely book or definitely refuse |
| Judge resolution | only **30 distinct values** across 801 people, four of them covering 341 |
| Elasticity, frame as shipped | **-1.432**, recommends cutting the rate |
| Elasticity, same inputs, neutral per-option wording | **-0.090**, recommends raising it |

That last pair is the headline. The LLM wrote "a third below the current rate" and
"two thirds above the current rate" into the options, and Jev read those as instructions.
The `-0.893` we had recorded as credible was an artifact. `normalize_frame` passes variant
text through with no content validation, and `FRAME_SYSTEM` explicitly says "the first
variant is the status quo", which invites exactly this.

## 3. Goals

1. A stranger can find JevFish, understand it in thirty seconds, and run it with one
   command that works.
2. JevFish never prints a number without saying what quantity it is and how wrong it has
   historically been.
3. JevFish refuses, loudly, when its answer came from its own prompt.

## 4. Non-goals

- Making JevFish predict occupancy. It produces a share of a described option set.
  Converting that to occupancy needs arrival volume, channel mix and listing visibility,
  none of which JevFish has. The tool will say so instead of pretending.
- Replacing booking-pace forecasting for Pureloft rates. The published state of the art
  there is own booking pace with a fitted elasticity, which delivered a 7.42 percent GMV
  lift in live A/B. JevFish is for ordering options and for counterfactuals with no
  history, not for setting the level.
- Paying for Apple notarization, freezing a binary, or a hosted interactive demo. All three
  are deferred with recorded reasons.

## 5. What gets built

### Track A: accuracy (10 tasks)

| # | Change | Why, with the number |
|---|---|---|
| 1 to 3 | Detect and refuse comparative per-option wording; neutralise it; tighten `FRAME_SYSTEM` | -1.432 against -0.090 on identical inputs |
| 4 | `scoring.py`: Brier, log score, CRPS, a level-versus-shape decomposition, skill score against a named baseline. No ECE, which is not a proper rule | Nothing in the codebase can currently score a prediction |
| 5 | `anchors.py`: resolved outcomes on disk, carrying `estimand`, `model_version` and `frame_hash` | 1 anchor buys a level shift, 5 buys level plus scale, 9 buys a 90 percent interval, about 70 buys near-optimal decisions |
| 6 | `calibrate.py`: `sigmoid(a + b*logit(q))` applied per persona before aggregation, plus split conformal | Removes the 32.4pp error. Monotone, so it can never reorder the options |
| 7 | `metrics.summarize_poll` reports the calibrated number, names the estimand, and says which kind of interval you are looking at | The 11.5x understatement |
| 8 | Randomise `ChoiceQ` option order per person, deterministic in the seed | Fixed order turns judge position bias into a systematic shift rather than noise |
| 9, 9b | Report whether the result survives neutral wording; block curves steeper than anything published or running the wrong way | Would have caught the -3.29 and the -1.432 |
| 10 | Regression tests pinning every measured number to the stored run | So none of this silently comes back |

## 6. What "done" looks like

| Measure | Now | Target |
|---|---|---|
| GitHub search for the repo name | 0 results | 1 |
| Install command | clone a fork, double-click an unsigned app | `uvx jevfish serve` |
| Core install size | 1,100 MB | under 120 MB |
| Wheel serves the UI | no, 404 | yes, HTTP 200, asserted in CI |
| Python versions | 3.12 only | 3.12 and 3.13, each verified before the claim is made |
| Can the tool score itself? | no | Brier, log score, CRPS, skill score against a baseline |
| Does it name its estimand? | no | yes, on every number |
| Does the interval cover model error? | no, 11.5x too narrow | yes above 4 anchors, and it refuses to print one below that |
| Does it flag prompt-driven results? | no | yes, blocks the run |

## 7. Risks

| Risk | Handling |
|---|---|
| Leaving the fork network is not reversible | Verified 0 stars, 0 forks, 0 issues, so nothing is lost. Mark decides, not me |
| Anchors are the binding constraint and we have one | Track A ships useful without them (frame gates, scoring, honest labelling). Calibration degrades gracefully: no anchors means the identity map and an explicit "uncalibrated" label |
| Pureloft's data cannot supply more anchors | Its measured elasticity is positive (+0.17 to -0.02) from simultaneity. The fix is deliberate randomised price variation, which is a separate piece of work, or public benchmarks |
| A calibration fitted on one Jev version silently transfers | `model_version` and `frame_hash` are required anchor fields |
| Widening `requires-python` on assumption | The plan verifies 3.13 with a real run before the claim ships, and says to narrow it if that fails |
| The name is taken or trademark-exposed | `jevfish` verified free on PyPI, npm and GitHub. One item genuinely open: a manual USPTO check of `JEV` in classes 9 and 42 before any commercial use |
